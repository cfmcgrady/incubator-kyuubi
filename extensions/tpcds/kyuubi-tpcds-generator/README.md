# Independent TPC-DS generation core

All **24 base tables** are generated by this module using only the JDK. Both the
Spark connector and the development data writer use this implementation for
all supported scales. There is no Trino generator, reflection adapter, JNI, or
native executable in either runtime path.

The compatibility reference is
[`databricks/tpcds-kit@1b7fb7529edae091684201fab142d956d6afd881`](https://github.com/databricks/tpcds-kit/tree/1b7fb7529edae091684201fab142d956d6afd881).
The executable reports **2.13.0**; the repository README's mention of 2.4 is
outdated. The fixed commit, build flags, command arguments, and output checksums
define the reference, rather than the old Java generator's output.

## Implementation and cursor contract

`TpcdsGenerator.partition` creates a `RowCursor` for any `TpcdsTable`.
`TpcdsGenerator.range` accepts a zero-based, half-open `RowRange`: its units are
parent orders for sales/returns and rows for dimensions/inventory. Partitioning
follows native boundaries. Tables with fewer than one million parent rows are
emitted only by partition 1; the other partitions are empty.

Each cursor owns its mutable state. Immutable distribution data are cached and
shared. Current values are valid after `next()` returns true and until the next
call to `next()`. Keys and integers use primitive `long` values, decimals use
unscaled cents, dates use Julian days, and nulls are stored separately. The Spark
adapter writes directly to a reusable `UnsafeRow`; the dev adapter returns an
independent text row. No per-row reflection is used.

The schema, scaling, random-stream contracts and output null-bit mappings are
owned by this module. The dev writer derives its schema from the same metadata,
including BIGINT order/ticket numbers, so large scales do not overflow an INT
cast during output. Existing connector column names and SQL types are preserved;
open-ended history dates are nullable even when the random null bitmap excludes
them. The legacy customer-column naming option remains supported.

Random offsets stay 64-bit. Seeking reduces exponents before multiplication to
avoid overflowing `long`, and per-row draw budgets detect accidental changes to
random consumption. Historical dimensions can resume inside a business key by
replaying at most two preceding revisions. Sales and returns use synchronized
parent-order streams, with bounded item permutations and reusable primitive
buffers.

Integer scales through 100000 and the zero/tiny (0.01) extensions are supported.
Nonstandard scales use native interpolation consistently for both dimensions
and fact-table foreign keys. Tiny has no native dsdgen counterpart and has its
own full-table connector count/checksum regression coverage.

## Intentional compatibility details

The reference output is preserved where it differs from conventional expectations:

- `store_sales` prints the coupon in both discount and coupon positions.
- Pointer-valued history attributes and item price flags follow the native
  retention behavior; they differ from the previous Java implementation.
- Store history dates use the native source-table offset. Date-dimension flags
  and calendar calculations retain the fixed reference's historical quirks.
- Large-scale call-center INTEGER arithmetic retains native 32-bit wrapping.
  A scale with an empty native random range is rejected instead of dividing by zero.
- Catalog sales retain native date allocation, including its boundary behavior
  when a partition starts exactly on a daily order boundary. Use the same
  partition arguments when comparing with native files.
- Benchmark dictionaries use their original ISO-8859-1 encoding. JVM strings
  preserve characters such as the country name `CÔTE D'IVOIRE` without replacement
  characters. Blank text and random/sentinel nulls remain distinct in the cursor.

These rules are covered by reference fixtures rather than inferred from matching
row counts. Changing them requires changing the declared compatibility target.

## Reference validation

Build the pinned reference outside this repository:

```bash
git checkout --detach 1b7fb7529edae091684201fab142d956d6afd881
cd tools
make OS=LINUX CFLAGS='-D_FILE_OFFSET_BITS=64 -D_LARGEFILE_SOURCE -DYYDEBUG -DLINUX -O3 -fcommon -std=gnu89' -j4 dsdgen
./dsdgen -scale 10000 -table store_sales -parallel 24000000 -child 23000001 -dir /path/to/output -force -quiet
```

`src/test/resources/native/reference-matrix.tsv` records 174 nonempty comparisons
at SF1, SF20, SF200, SF10000, SF30000 and SF100000: **10,256,423 rows** were compared
field for field. It records SHA-256 of the native text decoded from ISO-8859-1
and encoded as UTF-8. Sales commands also produce their returns table. Native
commands for non-first partitions of small tables produce no data file.

`native/all/manifest.tsv` selects 267 bounded samples from those outputs. Its
start/end columns are generator range offsets. Small dimensions are included in
full; larger dimensions have first, interior and tail samples. For small-scale
fact tables that cannot be partitioned natively, samples select the first 100
parent orders from the full native output. The gzip files contain original
native bytes and the manifest records their uncompressed SHA-256. Additional
store-channel fixtures in `native/manifest.tsv` cover the 32-bit boundary and
interior partitions. Tests require neither network access nor native tools.

```bash
build/mvn -pl extensions/tpcds/kyuubi-tpcds-generator -am test
```

Further tests exercise random seeking against an independent BigInteger oracle,
all six sales/returns tables across the integer boundary, historical range
resumption, empty partitions, invalid ranges, Unicode data, nullable schemas,
Spark typed conversion, and the dev text adapter. This validation does not
materialize a complete 10TB dataset.

## Performance

An opt-in Spark benchmark covers all 24 tables and consumes the generated
`UnsafeRow` contents, including initialization and string conversion:

```bash
RUN_BENCHMARK=1 build/mvn -pl extensions/spark/kyuubi-spark-connector-tpcds -am \
  -Dtest=none -DwildcardSuites=org.apache.spark.kyuubi.TPCDSCoreGenerateBenchmark test
```

Before removal of the old path, the store-channel benchmark generated one million
output rows at SF10000 on Java 21 / Scala 2.13 / Spark 4.0:

| Table | Previous best | Independent best | Relative throughput | Allocated bytes/row, previous → independent |
| --- | ---: | ---: | ---: | ---: |
| store_sales | 826 ms | 186 ms | 4.4× | 2035 → 31 |
| store_returns | 4734 ms | 934 ms | 5.1× | 9994 → 31 |

These measurements cover the store channel only. They are local generator
microbenchmarks, not end-to-end writes or TPC Benchmark Results, and are not
comparable to TPC Benchmark Results.

## Dictionary provenance

The generation algorithms are independent Java implementations. The 58 static
benchmark dictionary files are retained, byte for byte, from the resources in
`io.trino.tpcds:tpcds:1.4`, which declares Apache License 2.0. These are benchmark
data (names, weights, vocabulary and calendar entries), not Trino executable
code. Original TPC/Gradient Systems notices are preserved. See
`src/main/resources/META-INF/NOTICE-tpcds-dictionaries` for attribution and
`dictionary-sha256.tsv` for the original resource checksums. No native source,
executable or native distribution index is bundled.
